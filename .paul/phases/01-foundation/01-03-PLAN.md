<objective>
## Goal
Define all 10 port interfaces as TypeScript types in `core/ports/`, create the adapter registry that maps environment variables to implementations, and implement the first real adapter — Supabase AuthProvider.

## Purpose
The ports-and-adapters boundary is the most important architectural decision in fluxaOS. Every subsequent phase builds against port interfaces, never against vendor implementations. Getting the interfaces right now means all future adapter work is additive — no refactoring core code. The adapter registry makes provider selection a config change, not a code change.

## Output
- `src/core/ports/*.ts` — 10 port interface files + barrel export
- `src/config/registry.ts` — adapter registry (env → implementation mapping)
- `src/adapters/supabase/auth.ts` — Supabase AuthProvider implementation
- Zero vendor imports in `core/` — verified by grep
</objective>

    - getUser(): Promise&lt;User | null&gt;
    - onAuthStateChange(callback: (event: AuthEvent, session: Session | null) =&gt; void): Unsubscribe

    **git.ts — GitProvider:**
    - createBranch(repo: string, branch: string, fromRef?: string): Promise&lt;void&gt;
    - createPullRequest(params: CreatePRParams): Promise&lt;PullRequest&gt;
    - getPullRequest(repo: string, number: number): Promise&lt;PullRequest&gt;
    - listPullRequests(repo: string, state?: 'open' | 'closed' | 'all'): Promise&lt;PullRequest[]&gt;
    - mergePullRequest(repo: string, number: number, method?: 'merge' | 'squash' | 'rebase'): Promise&lt;void&gt;
    - Define: CreatePRParams, PullRequest (number, title, body, state, headBranch, baseBranch, url, createdAt)

    **issue.ts — IssueProvider:**
    - createIssue(repo: string, issue: CreateIssueParams): Promise&lt;ExternalIssue&gt;
    - updateIssue(repo: string, number: number, updates: Partial&lt;CreateIssueParams&gt;): Promise&lt;ExternalIssue&gt;
    - getIssue(repo: string, number: number): Promise&lt;ExternalIssue&gt;
    - listIssues(repo: string, state?: 'open' | 'closed' | 'all'): Promise&lt;ExternalIssue[]&gt;
    - syncFromExternal(repo: string, since?: Date): Promise&lt;ExternalIssue[]&gt;
    - Define: CreateIssueParams (title, body, labels, assignees), ExternalIssue (number, title, body, state, labels, url, createdAt, updatedAt)

    **ai.ts — AIProvider:**
    - complete(params: CompletionParams): Promise&lt;CompletionResult&gt;
    - stream(params: CompletionParams): AsyncIterable&lt;CompletionChunk&gt;
    - listModels(): Promise&lt;ModelInfo[]&gt;
    - healthCheck(): Promise&lt;boolean&gt;
    - Define: CompletionParams (model, messages, maxTokens, temperature, tools?), CompletionResult (content, usage: { inputTokens, outputTokens, costUsd }), CompletionChunk (type: 'text' | 'tool_use', content, usage?), ModelInfo (id, name, capabilities: string[])

    - process&lt;T&gt;(queueName: string, handler: (job: Job&lt;T&gt;) =&gt; Promise&lt;void&gt;): void
    - getJob(queueName: string, jobId: string): Promise&lt;Job | null&gt;
    - cancelJob(queueName: string, jobId: string): Promise&lt;void&gt;
    - Define: JobOptions (priority?, delay?, attempts?, backoff?), Job&lt;T&gt; (id, data: T, status, progress, attempts, failedReason?)

    **realtime.ts — RealtimeProvider:**
    - subscribe&lt;T&gt;(channel: string, event: string, callback: (payload: T) =&gt; void): Unsubscribe
    - broadcast&lt;T&gt;(channel: string, event: string, payload: T): Promise&lt;void&gt;
    - Define: Unsubscribe (() =&gt; void)

    **stage-executor.ts — StageExecutor:**
    - execute(params: ExecuteParams): Promise&lt;ExecuteResult&gt;
    - cancel(processId: string): Promise&lt;void&gt;
    - Define: ExecuteParams (command, args, cwd, env, timeoutMs, onStdout?, onStderr?), ExecuteResult (exitCode, stdout, stderr, durationMs, processId)

<task type="auto">
  <name>Task 2: Create adapter registry with env-based provider resolution</name>
  <files>src/config/registry.ts, src/config/index.ts</files>
  <action>
    Create the adapter registry that maps environment variables to adapter implementations.

    **src/config/registry.ts:**

    1. Define `AdapterType` union: 'auth' | 'git' | 'issue' | 'ai' | 'database' | 'queue' | 'realtime' | 'stage-executor' | 'notification' | 'storage'

    2. Define mapping of env var names to adapter types:
       ```
       auth → FLUXAOS_AUTH_PROVIDER (default: 'supabase')
       git → FLUXAOS_GIT_PROVIDER (default: 'github')
       issue → FLUXAOS_ISSUE_PROVIDER (default: 'github')
       ai → FLUXAOS_AI_PROVIDERS (default: 'anthropic') — note: comma-separated for AI
       database → FLUXAOS_DATABASE_PROVIDER (default: 'postgres')
       queue → FLUXAOS_QUEUE_PROVIDER (default: 'bullmq')
       realtime → FLUXAOS_REALTIME_PROVIDER (default: 'supabase')
       stage-executor → FLUXAOS_STAGE_EXECUTOR (default: 'node-exec')
       notification → FLUXAOS_NOTIFICATION_PROVIDER (default: 'none')
       storage → FLUXAOS_STORAGE_PROVIDER (default: 'local')
       ```

    3. Implement `AdapterRegistry` class:
       - Private `adapters` map: Map&lt;string, unknown&gt; (keyed by "type:provider", e.g. "auth:supabase")
       - `register&lt;T&gt;(type: AdapterType, provider: string, factory: () =&gt; T): void` — register an adapter factory
       - `get&lt;T&gt;(type: AdapterType): T` — resolve from env var, look up registered factory, instantiate (lazy singleton)
       - `getProvider(type: AdapterType): string` — read env var, return provider name
       - Throw descriptive error if adapter not registered: `No adapter registered for ${type}:${provider}. Available: [list registered]`

    4. Export singleton: `export const registry = new AdapterRegistry()`

    **src/config/index.ts:**
    - Re-export registry and AdapterType from registry.ts
    - Export a `getConfig()` function that returns resolved adapter names for all types (useful for debugging/status)

    **Rules:**
    - Registry is generic — it doesn't import any adapter implementations
    - Adapter registration happens in adapter files (e.g., adapters/supabase/index.ts calls registry.register)
    - The registry only stores factory functions, not instances — lazy instantiation
  </action>
  <verify>
    npx tsc --noEmit
    grep -r "supabase\|bullmq\|github\|anthropic" src/config/ --include="*.ts" || echo "CLEAN: No vendor imports in config/"
  </verify>
  <done>AC-2 satisfied: registry resolves adapters from env vars, supports all 10 types</done>

    Create the first real adapter — Supabase AuthProvider. This proves the ports-and-adapters pattern works end-to-end.

    **src/adapters/supabase/auth.ts:**

    1. Import `AuthProvider` and supporting types from `@/core/ports`
    2. Import `createBrowserClient` from `@supabase/ssr` (for client-side)
    3. Import `createClient` from `@supabase/supabase-js` (for server-side)

    4. Implement `SupabaseAuthProvider` class that satisfies `AuthProvider`:
       - Constructor takes `{ supabaseUrl: string; supabaseAnonKey: string }`
       - Internal: create Supabase client
       - `signIn`: calls supabase.auth.signInWithPassword, maps to AuthResult
       - `signUp`: calls supabase.auth.signUp, maps to AuthResult
       - `signOut`: calls supabase.auth.signOut
       - `getSession`: calls supabase.auth.getSession, maps to Session | null
       - `getUser`: calls supabase.auth.getUser, maps to User | null
       - `onAuthStateChange`: calls supabase.auth.onAuthStateChange, returns unsubscribe

    5. Map Supabase types to port types — the adapter is the translation layer:
       - Supabase AuthSession → port Session
       - Supabase User → port User
       - Supabase auth events → port AuthEvent

    **src/adapters/supabase/index.ts:**

    1. Import registry from `@/config`
    2. Import SupabaseAuthProvider
    3. Register the adapter:
       ```ts
       registry.register('auth', 'supabase', () => new SupabaseAuthProvider({
         supabaseUrl: process.env.NEXT_PUBLIC_SUPABASE_URL!,
         supabaseAnonKey: process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
       }))
       ```

    **Rules:**
    - This file CAN import from @supabase/* — it's in adapters/supabase/
    - It MUST satisfy the AuthProvider interface — tsc will enforce this
    - No Supabase types leak into the return values — map everything to port types
