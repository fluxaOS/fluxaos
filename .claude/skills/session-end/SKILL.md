## Autonomy Contract

You run unattended. No human is watching. Do not ask. Do not wait. Do not pause for confirmation. The user may be asleep, away from the machine, or calling you from a script.

**Allowed exits per invocation:** completion, `state:on-hold`, or `state:failed`.

- **Completion** — work done, issue transitioned to the next pipeline stage, clean exit.
- **`state:on-hold`** — the current issue cannot proceed because work is required in another repository/system, credentials or external services are unavailable, or the user must make a product/architecture decision. File one issue per distinct blocker, link each as a blocker of the current issue, comment the reason, apply `state:on-hold`, exit cleanly.
- **`state:failed`** — you attempted the work and the implementation broke. Comment what broke, apply `state:failed`, exit.

**Agents own local blockers.** There is no separate development team. If the blocker is in this repository, the current workspace, the local toolchain, templates, tests, docs, or agent workflow, fix it or route around it autonomously. Do not use `state:on-hold` for work the user would normally tell an agent to do.

**On-hold is narrow.** Use `state:on-hold` only for:
- required changes in another repository or external system outside the current issue's ownership;
- unavailable credentials, secrets, accounts, devices, or external services;
- destructive or irreversible operations not already authorized by the user;
- genuine product or architecture decisions that require the user personally.

**Not on-hold.** Do not use `state:on-hold` for missing helper commands, local environment drift, failing tests, unclear but discoverable errors, merge conflicts, missing docs, missing fixtures, worktree setup issues, broken scripts, or agent/tooling friction. Diagnose and repair those first.

**Defaults are required, not optional.** Unless `--inline` is explicitly passed with a specific issue number, run delegated (subagent + worktree). If automatic delegation is unavailable, create or use an equivalent isolated local route when possible. Never silently fall back to unsafe inline execution, but do not stop if you can preserve the required safety property yourself.

**Blockers are tickets after remediation.** File blocker issues only after a concrete self-remediation attempt fails, or when the blocker meets the narrow on-hold criteria above. Two qualifying blockers = two issues. Three = three. Link all as blockers on the current issue, then `state:on-hold`.

**No silent degradation.** Do not downgrade required behavior because a capability seems unavailable. Preserve the requirement another way, fix the capability, or make the failure explicit. Use `state:on-hold` only when the narrow criteria apply; otherwise continue remediation or use `state:failed` if your attempted implementation broke.

**Never invent an external owner.** When instructions don't cover a case, assume the agents own it unless it meets the narrow on-hold criteria. The user is the only human decision-maker; do not defer to an imaginary team.

**Never apply `state:human-hold`.** That label is reserved for humans deferring work. Agents exit via `state:on-hold` or `state:failed`.

# Session End
<!-- DO NOT EDIT this file directly. It is maintained by fhc sync and will be overwritten.
     Source: templates/skills/session-end/SKILL.md in fh-commons -->

Wrap up the current context session: summarize, hand off, and mark closed.

## Usage

```
/session-end                                  # Full wrap-up
/session-end --dry-run                        # Report only, skip destructive actions
/session-end --since "YYYY-MM-DDTHH:MM"       # Override start timestamp if marker missing
/session-end --since-last-commit-on-main      # Best-effort window from last main commit
```

**Arguments:** `$ARGUMENTS`

---

## Step 0: Parse Arguments

- `--dry-run` → set `DRY_RUN=true` (skip destructive actions and marker writes)
- `--since <iso>` → set `SESSION_START=<iso>` explicitly
- `--since-last-commit-on-main` → set `SESSION_START` from `git log -1 --format=%cI origin/main`

---

## Step 1: Locate Session-Start Marker

If `SESSION_START` is not already set from arguments, query memory and compare timestamps:

```bash
hippo memory list --category session --limit 10 --format json
```

From the returned entries, find the most recent one whose `tags` (or `subject`) indicate `session-start`, and the most recent one indicating `session-end`. Compare their `created_at` timestamps:

- If the latest `session-start` is newer than the latest `session-end`, set `SESSION_START` to the latest `session-start` entry's `created_at`.

- If the latest `session-end` is newer than or equal to the latest `session-start`, set `SESSION_START` to the latest `session-end` entry's `created_at` and set `SESSION_BOUNDARY_REASON="No newer session-start marker; using latest session-end as fallback boundary."`

- If no `session-start` entry exists but a `session-end` entry exists, set `SESSION_START` to the latest `session-end` entry's `created_at` and set `SESSION_BOUNDARY_REASON="No session-start marker found; using latest session-end as fallback boundary."`

- If no session markers exist and no `--since*` override was given, set `SESSION_START` from `git log -1 --format=%cI origin/main` and set `SESSION_BOUNDARY_REASON="No session markers found; using last origin/main commit as fallback boundary."`

Do not stop just because `/session-start` was missed. A missing or stale start marker changes the boundary reason recorded in the handoff; it does not block session-end.

If memory queries fail entirely (DB unreachable), stop with the error and instruct the user to fix memory and re-run.

---

## Step 2: Recap

Pull activity since `SESSION_START`:

```bash
git log --since="$SESSION_START" --oneline
git log --since="$SESSION_START" --merges --pretty='%h %s' origin/main
 issue list --state closed --since "$(echo "$SESSION_START" | cut -c1-10)"
```

Group the commits by theme or EPIC. Write 2-3 observations about what was built, what's still in flight, and anything notable for next session. Prose in your own words — no fixed template.

---

## Step 3: Write Handoff Document

Write a non-overwriting handoff under `docs/superpowers/handoffs/`.

Location convention: `docs/superpowers/handoffs/YYYY-MM-DD-<topic>-session-handoff.md`. Use the session date in the filename. Derive `<topic>` using this deterministic chain (no user prompting):

1. **Conventional Commit scope** — read the topmost commit in the session window:
   ```bash
   git log --since="$SESSION_START" -1 --format=%s
   ```
   If the subject matches the Conventional Commits pattern `type(scope): message`, extract the scope. Strip anything outside `[a-z0-9-]`, lowercase, truncate to 40 characters.

2. **Most-touched directory** — if step 1 yields nothing (no scope or no commits), find the most-changed directory:
   ```bash
   git log --since="$SESSION_START" --name-only --pretty=format: \
     | grep -v '^$' | awk -F/ 'NF>1{print $1"/"$2} NF==1{print $1}' \
     | sort | uniq -c | sort -rn | head -1 | awk '{print $2}'
   ```
   Slugify the result: lowercase, replace `/` and `_` with `-`, strip non-`[a-z0-9-]`, truncate to 40 characters.

3. **Literal fallback** — if neither step 1 nor step 2 yields a usable slug (e.g., no commits this session), use `general`.

Never overwrite an existing handoff. If the target filename already exists, append `-2`, then `-3`, and so on before `.md` until the path is unused:

```
docs/superpowers/handoffs/YYYY-MM-DD-<topic>-session-handoff.md
docs/superpowers/handoffs/YYYY-MM-DD-<topic>-session-handoff-2.md
docs/superpowers/handoffs/YYYY-MM-DD-<topic>-session-handoff-3.md
```

Structure matches what actually happened — if nothing shipped, it's a short file. Include only sections that apply:

- What was accomplished (grouped by theme/EPIC)
- Session boundary used, including `SESSION_BOUNDARY_REASON` when set
- Issues closed this session
- Issues still in progress
- Open PRs awaiting action
- UI / integration test results (if project has a webapp)
- Known blockers
- Unfinished work (branch names, issue numbers)
- Context decisions made this session
- Next session: recommended starting point

Header: project name, session-end timestamp, model name, branch, and commit SHA.

If `DRY_RUN=true`, print the content to stdout instead of writing the file.

---

## Step 4: Ship Pending Work

If `DRY_RUN=true`, skip this step.

Assess pending work:

```bash
 git status --full
git log --oneline "origin/$(git branch --show-current)..HEAD" 2>/dev/null || \
  git log --oneline main..HEAD 2>/dev/null || true
```

<!-- auto-clarity:start -->
If there are uncommitted changes (excluding the handoff doc) or unpushed commits on feature branches (user-invoked `/session-end` — interactive option prompt is the intended user-facing UX):

```
Pending work detected:
  <summary of dirty files and unpushed branches>

Options:
  (y) ship — commit/push/PR via ` git finish` where appropriate
  (w) wip  — save as WIP commit: git add . && git commit -m "WIP: session-end $(date -I)"
  (n) leave — note in handoff and continue
```
<!-- auto-clarity:end -->

> **Never use `git stash`.** Stash lives in the shared `.git/refs/stash` and causes cross-agent
> mixing in multi-agent environments. Use WIP commits instead.

- **y**: commit the handoff doc separately with ` git finish -n -t "docs: session handoff $(date +%Y-%m-%d)"`. For each feature branch with unpushed commits tied to an issue, run ` git finish <issue-number>`.
- **w**: run `git add . && git commit -m "WIP: session-end $(date -I)"`; note the WIP commit SHA in the handoff doc.
- **n**: add an "Unfinished Work" note to the handoff doc.

## Step 6: Write Session-End Marker

If `DRY_RUN=true`, skip this step.

```bash
hippo memory add session "session-end" \
  --tags "session-end" \
  --body "Session ended at $(date -Iseconds). Handoff: <relative path to docs/superpowers/handoffs/...md>. Repo clean."
```

The `Handoff:` field in the marker body is the **canonical latest-handoff pointer**. The next session's resume step reads it by running:

```bash
hippo memory list --category session --tags session-end --limit 1 --format json
```

and parsing the `body` field for the `Handoff:` path. No symlink, no glob-and-sort — the memory entry is the single source of truth for the most recent handoff location.

If the command fails, stop and report. The marker is the close signal — do not print the success line without it.

---

## Step 7: Next-Session Prompt

Skip silently if nothing durable was produced this session (no commits, no specs, no plans, no closed issues).

Otherwise, print a copy/paste block under 150 words naming the active branch, in-flight spec/plan paths, and the next concrete action. Use your judgment on the exact wording; the goal is that the next session can resume without re-deriving context.

## Step 8: Worktree Self-Teardown

<!-- DO NOT EDIT this file directly. It is maintained by fhc sync and will be overwritten.
     Source: templates/partials/worktree-self-teardown.md in fh-commons -->

If running in an isolated worktree, tear it down after all work is complete:

```bash
WORKTREE_DIR=$(git rev-parse --show-toplevel)
MAIN_DIR=$(git worktree list | head -1 | awk '{print $1}')
if [ "$WORKTREE_DIR" != "$MAIN_DIR" ]; then
    PROJECT_NAME=$(basename "$MAIN_DIR")
    WORKTREE_BASENAME=$(basename "$WORKTREE_DIR")
    SLUG="${WORKTREE_BASENAME#${PROJECT_NAME}-}"
    cd "$MAIN_DIR"
     worktree end "$SLUG"
fi
```

` worktree end` verifies the branch is merged and the tree is clean before removing. Exit codes: 0 OK · 1 not merged · 2 dirty tree · 3 slug not found · 4 teardown failed. On non-zero exit, leave the worktree in place and log the error — do not force-remove.
