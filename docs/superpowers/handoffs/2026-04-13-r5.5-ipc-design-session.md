## Key Architectural Decisions

### 1. Stdout JSON signals, not tmux/Redis/MCP

Skills emit a `flux:signal` JSON line to stdout. The stage-runner recognizes it by the `flux:` namespace prefix. Last signal wins. No new infrastructure needed — the stdout capture path already exists.

**Why not the alternatives:**
- tmux: Solves problems from PAT's interactive mode that `--print` doesn't have
- Redis: Claude can't publish to Redis without an MCP tool, which adds the same complexity
- MCP tool/local API: Unnecessary server infrastructure for what amounts to "tell me what happened"
- Post-hoc parsing: Inferring intent from natural language is fragile

### 2. Skill signal is gate input, not authority

The skill emits a verdict (`proceed`/`hold`/`rework`/`abort`) but it's just another data point for gate rules. The gate engine remains the single decision authority. Gate rules can reference `skill_signal` as a field — or ignore it entirely.

**Why:** Avoids dual authority. If the skill signal could override gates, there's no clear answer when they disagree. With this design, the user controls routing via gate rules.

### 3. No fallbacks — missing signal = failure

Skills must emit a `flux:signal` line. If no signal is found after process exit, the stage run fails with `error_message: "no skill signal emitted"`. No inferring from exit code.

**Why:** Project principle. Misconfiguration surfaces immediately.

### 4. Switch from `--print` to `--output-format stream-json`

The current `--print` flag outputs plain text, which the parser can't structure. Switching to streaming JSON gives real-time output, typed transcript entries (text, tool_call, tool_result), and fixes the batching bug where output only appears when the run completes.

### 5. Output format is harness config, not hardcoded

New `output_format` and `output_format_flag` columns on `harness_catalog`. The command builder reads these to set the right CLI flag. Different harnesses can emit different formats. The stage-runner selects the parser based on `output_format`.

## Schema Changes (Not Yet Applied — In Plan)

**`stage_run` — 4 new columns:**
- `skill_signal` (text) — verdict from the skill
- `skill_metadata` (jsonb) — summary, PR #, branch, etc.
- `trigger` (text, not null, default 'manual') — who initiated
- `error_message` (text) — first error for quick access

**`harness_catalog` — 2 new columns:**
- `output_format` (text, not null, default 'stream-json') — parser selection
- `output_format_flag` (text) — CLI flag name (e.g., `--output-format`)
