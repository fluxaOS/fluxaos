7. **Stage runner (core integration)** — Rewrote subprocess handling to: use per-harness parser via `getParser()`, intercept `flux:signal` lines via `parseSignalLine()` (last signal wins), fail stages with no signal emitted, pass trigger type through to completion, include skill metadata in stage run records.

9. **Seed data** — Harness now uses `output_format: 'stream-json'` and `output_format_flag: '--output-format'`. Removed `--print` from `defaultArgs`.
10. **Gate tests** — 3 new tests verifying gate rules can reference `skill_signal` as a field (pass, fail, combined with exit_code).

## Known Issues / Watch For

1. **`--output-format stream-json` flag** — This is assumed to be a valid Claude CLI flag. If it doesn't exist or uses a different name, the first manual stage run (Task 14) will surface the issue. Check `claude --help` to verify.

2. **All manual runs will now fail** — Existing skills don't emit `flux:signal` lines. After merge, every stage run will fail with "no skill signal emitted". This is correct no-fallback behavior per project principles. Skills need updating as immediate follow-up work.

3. **TypeScript closure narrowing** — The `lastSignal` variable is mutated inside the `onStdout` callback but TypeScript's control flow analysis doesn't track this. Fixed with `null as SkillSignal | null` widening pattern. If future changes touch this area, be aware of this TS limitation.

4. **Migration applied via `drizzle-kit push`** — The `npm run db:migrate` command hung (known Supabase pooler issue for DDL), so `npx drizzle-kit push` was used instead. The migration file exists in `drizzle/` for reference but was not the mechanism that applied the schema change.
