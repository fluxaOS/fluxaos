# FLX-239 Stage 7 — E2E spec updates (FLX-266)

> Slice plan for Stage 7 of the tenancy-waterfall epic
> ([epic plan](2026-05-18-tenancy-waterfall-epic.md), Linear FLX-266).
> Stages 1–6 are merged; URL addressing is UUID-only (`/p/{uuid}/...`),
> access semantics are decided and shipped (FLX-269, `b41026e`).

## Goal

Make the full Playwright suite green under the post-FLX-239 product surface:
wire a producer for `FLUXAOS_PROJECT_ID`, retire the dead slug env vars, and
rewrite every spec that still encodes the slug-era URL tree or pre-Stage-5
router shapes.

## Scope

### 1. `FLUXAOS_PROJECT_ID` producer

- `src/scripts/db/seed-ids.ts` (new) — `SEED_PROJECT_ID =
  '00000000-0000-4000-8000-000000000001'`, a fixed constant. Lives in its own
  module because `seed.ts` executes on import.
- `src/scripts/db/seed.ts` — default project inserted with `id:
  SEED_PROJECT_ID`, so the env value survives every nuke + reseed.
- `tests/verify/seed-check.ts` — asserts `project.id === SEED_PROJECT_ID`.
- `.env.example` + `.env.local` — `FLUXAOS_PROJECT_ID=<the constant>` replaces
  the dead `FLUXAOS_ORG_SLUG` / `FLUXAOS_USER_SLUG` / `FLUXAOS_PROJECT_SLUG`
  block (slug-based addressing is gone — epic Stage 7 hard rule).
- No fallbacks: `e2e/helpers/setup.ts` still throws at module load when the
  env var is missing; no code path defaults to the constant.

### 2. Skip-gated spec rewrites

- `e2e/team-crud.spec.ts` — un-skipped for the org-scoped team model
  (create → edit → delete round-trip on Settings → Teams). New
  `cleanupTeamCrudRows()` sweep in `e2e/helpers/catalog-cleanup.ts` keeps the
  seed-check's exactly-one-team assertion meaningful after failed runs.
- `e2e/flx-252-create-entity-form.spec.ts` — Teams + Skills cases
  un-skipped. The Skills form's Scope select survives as a UI alias
  (`global` → `kind='catalog'`, `project` → `kind='project'`).
- `e2e/settings-url-context.spec.ts` — rewritten for `/p/{uuid}` paths and
  the Stage 5 `project.create` shape (`orgId` + `teamId` + `userId`; the
  service writes the `project_member` grant — membership setup per the epic
  hard rule). Bogus case uses a valid-but-unknown UUID.

### 2b. Suite-wide determinism (surfaced by the first full-suite run)

The first full Playwright run since Stages 4–6 merged exposed two systemic
conflicts between the suite and the live operator daemon (the
full-issue-lifecycle contract requires that daemon to be running):

- **Reseeds destroyed operator config.** ~21 specs nuke+seed inline; the
  seed leaves `project.target_repo_path` null (operator-owned, FLX-221), so
  every reseed broke all later daemon-dependent specs. New shared helper
  `e2e/helpers/reset-db.ts` (`resetDb()`) captures the operator's value
  before the nuke and restores it after the seed; all nuking specs now use
  it. The three temp-fixture daemon specs (cancel-stage-button,
  daemon-sigterm-graceful-drain, deploy-conflict-journey) additionally
  restore the operator value in `afterAll` before deleting their temp repos.
- **The watcher auto-dispatched the seed issues on every reseed**, racing
  fixture stage-swaps (FK violations on `stage_run`) and keeping "Run
  Stage" busy on issue #1. `resetDb()` now parks the seed issues at the
  'blocked' status (`quiesceSeedIssues()`) and clears any runs dispatched
  in the race window. To make parking deterministic, the IssueWatcher
  re-reads issue state at dispatch time instead of trusting the (stale)
  Realtime payload (`src/core/orchestrator/issue-watcher.ts`).

### 4. Product bugs found by the rewrites (root-cause fixes, same PR)

- `src/core/services/project.ts` — `project.delete` could never succeed:
  `create` always writes a `project_member` grant and the bare row delete
  trips the FK. `remove()` now deletes the project's membership grants in the
  same transaction. All other FKs still block — fail-fast preserved for
  projects with real content.
- `src/core/services/team.ts` — `listByProject` joined on `project.team_id`
  and returned only the owning team, so freshly created org-scoped teams
  never appeared in Settings → Teams. Now returns every team in the
  project's org (the surface `team.create` writes to).
- `src/app/p/[projectUuid]/settings/skills/page.tsx` — list rows lost their
  scope subtitle when `skill.scope` became `kind`; the page now maps
  `kind` → the UI scope alias ('global'/'project') so the subtitle and the
  create form's Scope select agree.
- `drizzle/0031_flx_266_config_entry_unique_idx.sql` — schema.ts has
  declared `config_entry_scope_project_key_idx` since FLX-222 but no
  migration ever created it; `ON CONFLICT ("scope","project_id","key")`
  failed at runtime and duplicates were silently allowed. Hand-written
  migration adds the unique index.
- `src/components/record-editor/RecordEditor.tsx` — `data-testid`
  on the records list so specs can scope away from nav `<li>`s.
- `drizzle/0032_flx_266_realtime_publication.sql` — the FLX-239 Stage 1
  rip-and-replace migration dropped + recreated most tables, silently
  removing them from the `supabase_realtime` publication. Live subscribers
  broke: ActivityFeed (`issue_event`), LiveOutput (`event`), RunDetailModal
  (`stage_run`), mission-control (`issue_pull_request`). Idempotent
  hand-written migration re-adds the four tables.
- Driver observability regression (surfaced by `live-output-streaming` and
  `cancel-stage-button`): the langgraph stage runner executed drivers via
  buffered `execFileAsync`, which never exposed the child pid (breaking
  cancel-by-pid and the recovery sweep) and discarded stdout until exit
  (breaking LiveOutput event streaming). Fixes:
  - `src/core/ports/stage-graph-runner.ts` — `StageGraphInput` gains
    optional `onDriverStart(pid)` / `onDriverStdout(line)` callbacks.
  - `src/adapters/langgraph/langgraph-stage-runner.ts` — drivers run via
    `spawn` with line-buffered stdout streaming; callbacks ride outside
    graph state (checkpointer-safe `driverCallbacks` map keyed by
    stageRunId). Spawn-level failures (missing binary, EACCES) are now
    engine errors instead of being swallowed as "agent exited non-zero".
  - `src/core/orchestrator/stage-executor.ts` — persists the driver pid on
    spawn (`runService.recordPid`) and streams parsed stdout lines into
    output events; both writes are fire-and-forget so observability never
    blocks execution. Also guards post-execution bookkeeping behind a
    `wasCancelled()` re-read so the Cancel endpoint's mid-flight
    cancellation is never overwritten by completion/verdict routing.
  - `src/core/orchestrator/event-orchestrator.ts` + `src/scripts/daemon.ts`
    — the daemon injects the registry's `stdoutParser` so the executor can
    shape driver stdout into transcript entries.
- `e2e/helpers/daemon.ts` — optional `FLUXAOS_E2E_DAEMON_LOG` disk tee for
  spec-spawned daemons (postmortem visibility; off when unset).

## 5. Full-suite gate fallout (second pass)

Running the complete suite against the live operator daemon surfaced a
further layer of conflicts. All root-caused, none worked around:

- **Cancellation leaked isolation envs** (`cancel-stage-button`): the
  FLX-266 `wasCancelled()` guard returned early without firing the terminal
  hook, so the Cancel endpoint's env was never released. The guard now
  routes through `finishRun(run, cancelled)` — re-affirms the same status
  (never an overwrite) and the hook releases the env + drains the queue
  (`src/core/orchestrator/stage-executor.ts`).
- **Issue deleted mid-stage ended `blocked`, not `failed`**
  (`issue-deleted-mid-pipeline`): the modern verdict router fell through to
  null-routing → blocked when the issue vanished. `applyVerdict` now
  re-reads the issue at the stage boundary and fails the run (terminal hook
  releases the env) when it is gone — the documented FLX-86 contract.
- **`target_repo_path` leak poisoned later journeys**: three temp-repo
  daemon specs (`issue-deleted-mid-pipeline`, `live-output-streaming`,
  `stage-failure-rework-verdict`) pointed the seed project at their temp
  fixture repo and deleted it without restoring the operator value —
  `resetDb()`'s capture/restore then faithfully preserved the broken path
  for the rest of the suite, failing every later real-Claude journey at
  isolation acquire (`ENOENT <tmpdir>/.gitignore`). All three now use the
  same capture/restore pattern as cancel/drain/deploy-conflict.
- **Suite-order coupling on seed issue #1**: `r-daemon-autonomous-run`,
  `r-mission-control`, and `real-anthropic-stage-run` assumed pristine seed
  state but ran after `r-epic-hierarchy` (which closes issue #1 under an
  epic hierarchy). Each now calls `resetDb()` in `beforeAll`.
- **Wrong-port fallbacks in spec-side tRPC calls**: `r-epic-hierarchy`,
  `r-smoke`, and `r-artifacts-chain` built absolute URLs from
  `PLAYWRIGHT_BASE_URL ?? 'http://localhost:3003'` (the UAT port — a
  latent no-fallbacks violation that pointed dev-suite traffic at UAT when
  the env var was unset). They now use relative URLs via `page.request`,
  which resolves against the single configured Playwright `baseURL`.
- **Daemon-claim race in the drain journey**
  (`daemon-sigterm-graceful-drain`): pipeline_run claims are a Realtime
  race between the operator daemon and the spec-spawned daemon. Drain
  semantics only hold for a run the spec daemon owns, so the spec retries
  (bounded) until its daemon wins the claim, verified via `/proc` pid
  ancestry, and scopes its drained-count assertion to the owned run. The
  pid-event poll also requires stage-running AND pid-event in one query
  (the old two-phase poll raced the event write).
- **Stub-driver prompt assumptions retired**: prompt composition is
  persona-based (FLX-106) — driver `issue_prompt_template` placeholders
  like `{{workspace_path}}` are never rendered into argv. The
  `deploy-conflict-journey` stub now takes the worktree from
  `process.cwd()` (the executor sets driver cwd to the isolation env);
  the `stage-failure-rework-verdict` stub was rewritten to the modern
  result-doc contract: it updates `RESULT_DOC_PATH` with verdict
  `fail` (review) / `pass` (rework), discriminating on `doc.run.stage`,
  and the fixture routes via `on_fail`/`on_pass` instead of the legacy
  `skill_signal` gate rules + `issues.state.on_rework_key` config (which
  have no consumer in the modern engine).
- **`deploy-conflict-journey` asserted pre-FLX-197 semantics**: it expected
  a deploy push conflict to fail the pipeline/stage rows. The engine
  (correctly, FLX-197) records the failure on the run's own `deploy_run`
  row, keeps pipeline rows `completed`, and releases the env after the
  deploy failure. The spec now asserts the `deploy_run` contract.
- **`real-anthropic-stage-run` demanded an impossible tool_call entry**:
  the seeded Claude driver runs with `--disallowedTools` for every tool, so
  live runs can never emit tool_call transcript entries. The DEF-011
  surface (output events flow DB → renderer) is now asserted via a
  non-empty live-output pane instead.
- **`project-crud` missed the FLX-227 validate gate**: a changed repoUrl
  blocks Save until the field's Validate button confirms it; the spec now
  validates before saving (mirrors `settings-projects-form-slice`).
- **`auto-dispatch` poll raced hydration**: visibility was checked
  immediately after `page.reload()` before client queries resolved; each
  iteration now waits for the run indicator.
- **State leak into `delete-a-referenced-driver`**: daemon fixtures rewire
  the seed pipeline's stages to stub drivers, breaking the "Claude Code is
  referenced" precondition; the spec now resets the DB first.
- **Create-invalidation race (FLX-279)**: creating a record while the
  page's initial list fetch is in flight loses the post-create
  invalidation to react-query request dedupe — the new row never appears
  without a reload. Filed as a product bug; the two skills delete specs
  are hardened (wait for the seeded row before creating / reload-poll
  after create).
- **`feature-gated-tier` could only pass vacuously**: the suite runs under
  `FLUXAOS_LAN_AUTH_BYPASS=1`, where `resolveViewer` PINS the viewer tier
  to 'enterprise' and never consults `organization.subscription_tier` — so
  "flip the org to free and the panel disappears" is untestable through
  this surface (the old assertion passed only when it raced the panel's
  render). Rewritten to assert the true bypass contract: the enterprise
  viewer sees the revision-history panel and org-tier flips do not change
  it. Tier-gate enforcement keeps its real coverage in
  `src/__tests__/integration/feature-gated-tier.test.ts`.
- **`quiesceSeedIssues` cleanup raced straggler executor inserts**: a
  stage_run/isolation_environment row landing between the sequential
  DELETEs broke the pipeline_run delete (FK). The sweep now also clears
  `deploy_run` and retries up to 3 times — stragglers stop once the park
  is visible to the watcher's dispatch-time re-read.
