<objective>
## Goal
Implement skill registry with full CRUD, DB-to-disk materializer, and tRPC routes — completing the second pillar of Phase 2 project management.

## Purpose
Skills are the unit of capability in fluxaOS. Personas consume skills, the pipeline engine materializes them to disk at execution time, and harnesses read them as files. This plan builds the entire skill lifecycle: store in DB, manage via API, sync to filesystem.

## Output
- `core/skills/` — types, service layer, materializer
- tRPC skill router with full CRUD + materialize endpoint
- Tests covering CRUD, versioning, and materialization
</objective>

<task type="auto">
  <name>Task 1: Skill types, service layer, and materializer</name>
  <files>src/core/skills/types.ts, src/core/skills/service.ts, src/core/skills/materializer.ts, src/core/skills/index.ts</files>
  <action>
    **types.ts:**
    - Define SkillScope union: 'global' | 'project'
    - Define CreateSkillInput interface: name (required), description?, promptTemplate?, inputSchema?, outputSchema?, tags?, scope?, projectId?
    - Define UpdateSkillInput interface: all fields optional, no id
    - Define SkillFilter interface: projectId?, scope?, tags?

    **service.ts:**
    Follow the issue service pattern exactly:
    - createSkill(input: CreateSkillInput) — insert into skill table, return created row
    - getSkill(id: string) — select by id, throw if not found
    - listSkills(filters?: SkillFilter) — filter by projectId/scope/tags, order by name
    - updateSkill(id: string, updates: UpdateSkillInput) — update fields + auto-increment version, return updated row
    - deleteSkill(id: string) — soft or hard delete (hard delete for alpha simplicity)
    - Import db and skill table from core/db/schema

    **materializer.ts:**
    - materializeSkills(projectId: string, targetDir: string) — core function
    - Query all skills for the project from DB
    - For each skill: write a file `{targetDir}/{skill.name}.md` containing frontmatter (id, version, tags, scope) + prompt template body
    - After writing, scan targetDir for .md files not matching any current skill name — delete stale files
    - Use Node.js fs/promises (mkdir -p targetDir, writeFile, readdir, unlink)
    - Return { written: number, cleaned: number }

    **index.ts:**
    - Barrel export: all types, all service functions, materializeSkills
  </action>

  <done>AC-1 satisfied: CRUD functions typed and implemented. AC-2 satisfied: materializer writes and cleans files.</done>
