<objective>
## Goal
Implement the issue lifecycle service with database CRUD, wire it into the tRPC issue router with full endpoints, and create the GitHub IssueProvider adapter for bidirectional sync.

## Purpose
Phase 2's core value is self-management — fluxaOS tracks its own work. Issues are the fundamental unit of work. This plan establishes issue CRUD (create, read, update, list, state transitions), activity logging via IssueEvent, and GitHub sync so issues exist in both fluxaOS and GitHub.

## Output
- Issue service in `core/issues/` with CRUD + state transitions + event logging
- tRPC issue router with full endpoints replacing the stub
- GitHub IssueProvider adapter implementing the IssueProvider port
- Tests verifying issue service logic
</objective>

  <name>Task 1: Issue service with CRUD and state transitions</name>
  <files>

  <action>
    1. Create `src/core/issues/types.ts`:
       - Define IssueState union: "open" | "in_progress" | "blocked" | "closed"
       - Define IssuePriority union: "low" | "medium" | "high" | "critical"
       - Define IssueType union: "task" | "bug" | "feature" | "research"
       - Define CreateIssueInput: { projectId, title, description?, priority?, type?, createdBy?, source? }
       - Define UpdateIssueInput: Partial of title, description, priority, type
       - Define IssueWithEvents type joining issue + events

    2. Create `src/core/issues/service.ts`:
       - Import db from `@/core/db`
       - Import schema tables: issue, issueEvent
       - Functions (all async, take db as parameter for testability):
         - `createIssue(input: CreateIssueInput)`: Insert issue, log "created" event, return issue
         - `getIssue(id: string)`: Query with events relation, throw if not found
         - `listIssues(projectId: string, filters?: { state?, type? })`: Query with optional filters, order by createdAt desc
         - `updateIssue(id: string, updates: UpdateIssueInput)`: Update fields, log "updated" event, return updated
         - `transitionIssue(id: string, newState: IssueState)`: Validate transition, update state, log "state_changed" event with { from, to } payload
       - Valid transitions: open → in_progress/blocked/closed, in_progress → blocked/closed/open, blocked → open/in_progress, closed → open
       - Throw on invalid transition (e.g., closed → in_progress directly)

    3. Create `src/core/issues/index.ts`:
       - Barrel export: types + service functions

    4. Create `src/__tests__/issues.test.ts`:
       - Test createIssue returns issue with correct defaults
       - Test transitionIssue enforces valid transitions
       - Test transitionIssue rejects invalid transitions
       - Use createCallerFactory to test via tRPC (after Task 2)
       - Note: Tests that need DB can use mocked Drizzle or test against real DB

    Avoid: Importing from adapters/ — core/issues/ must be vendor-free.
    Avoid: Over-engineering state machine — simple switch/map of valid transitions is sufficient.
  </action>
  <verify>
    - `tsc --noEmit` passes
    - `npx vitest run` — issue tests pass
  </verify>
  <done>AC-1 satisfied: CRUD works. AC-2 satisfied: state transitions enforced and logged.</done>

      - Input: { projectId: z.string().uuid(), state: z.enum([...]).optional(), type: z.enum([...]).optional() }
      - Calls listIssues service

    - `issue.getById` — query
      - Input: { id: z.string().uuid() }
      - Calls getIssue service
      - Returns issue with events

    - `issue.update` — mutation
      - Input: { id: z.string().uuid(), title: z.string().optional(), description: z.string().optional(), priority: z.enum([...]).optional(), type: z.enum([...]).optional() }
      - Calls updateIssue service
      - Returns updated issue

    - `issue.transition` — mutation
      - Input: { id: z.string().uuid(), state: z.enum([...]) }
      - Calls transitionIssue service
      - Returns updated issue

    Avoid: Auth middleware — Phase 2 doesn't add auth to routes yet.
    Avoid: Pagination — keep simple for alpha, add later if needed.

       - Constructor takes `{ token: string }` (from GITHUB_TOKEN env var)
       - Use native fetch (no Octokit dependency for alpha):
         - Base URL: https://api.github.com
         - Auth: Bearer token header
         - Content-Type: application/json
       - Implement all IssueProvider methods:
         - `createIssue(repo, params)`: POST /repos/{owner}/{repo}/issues
         - `updateIssue(repo, number, updates)`: PATCH /repos/{owner}/{repo}/issues/{number}
         - `getIssue(repo, number)`: GET /repos/{owner}/{repo}/issues/{number}
         - `listIssues(repo, state?)`: GET /repos/{owner}/{repo}/issues?state={state}
         - `syncFromExternal(repo, since?)`: GET /repos/{owner}/{repo}/issues?since={iso}&state=all
       - Map GitHub API response to ExternalIssue type from port
       - Handle errors: throw on non-2xx responses with status + message

       - Import registry from `@/config/registry`

       - Ensure IssueProvider is in the port type mapping

    Avoid: Importing GitHub adapter in core/ — containment boundary must hold.
