<objective>
## Goal
Build a minimal CLI that wraps the tRPC API — `fluxaos issue list/create/view`, `fluxaos skill list/sync`, and `fluxaos status`. Completes Phase 2 project management.

## Purpose
The CLI makes fluxaOS self-managing from the terminal. Developers interact with issues and skills without needing the web UI. This is the third and final pillar of Phase 2.

## Output
- `src/cli/` — standalone tRPC client, command dispatcher, domain commands
- `package.json` bin entry + CLI script
- Tests covering command parsing and output formatting
</objective>

<task type="auto">
  <name>Task 2: Issue, skill, and status command handlers</name>
  <files>src/cli/commands/issue.ts, src/cli/commands/skill.ts, src/cli/commands/status.ts</files>
  <action>
    Each command file exports a single async function taking (client, args).

    **issue.ts — handleIssueCommand(client, args):**
    - `list --project <uuid>` → client.issue.list.query({ projectId }) → format as table (title, state, priority, type)
    - `create --project <uuid> --title <str> [--type <str>] [--priority <str>]` → client.issue.create.mutate() → print created issue
    - `view <uuid>` → client.issue.getById.query({ id }) → print full detail
    - Unknown subcommand → print issue help

    **skill.ts — handleSkillCommand(client, args):**
    - `list [--project <uuid>]` → client.skill.list.query() → format as table (name, scope, version, tags)
    - `sync --project <uuid> --dir <path>` → client.skill.materialize.mutate({ projectId, targetDir }) → print written/cleaned
    - Unknown subcommand → print skill help

    **status.ts — handleStatusCommand(client, args):**
    - Call client.health.check.query() → print "fluxaOS is running" with status details
    - On connection error → print "fluxaOS server not reachable at <url>"

    **Formatting:**
    - Use simple console.log with padEnd() for table alignment — no chalk/cli-table dependency
    - Keep output minimal and scannable
  </action>
  <verify>tsc --noEmit passes with command files</verify>
  <done>AC-2 satisfied: issue commands. AC-3 satisfied: skill commands. AC-4 satisfied: status command.</done>
</task>
